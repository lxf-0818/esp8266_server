# main.cpp

## Purpose
Implements the ESP8266 server runtime that accepts TCP commands on port `8888`,
returns sensor payloads for `ALL`, and dispatches non-`ALL` commands to system task handlers.

## Setup Sequence
`setup()` currently performs this flow:
1. Starts serial at `115200`.
2. Sets `LED_BUILTIN` to output and drives it HIGH (off state on ESP8266 boards).
3. Starts a loop watchdog ticker (`LWD_TIMEOUT = 600000 ms`).
4. Calls `configSensors(sensorName)` to detect supported I2C and 1-wire sensors.
5. If sensors are found:
	- Prints each detected I2C device mapping using `printDevice(i)`.
	- Starts the TCP server with `server.begin()`.
	- Connects/registers via `beginWIFI(sensorName)`.
	- Clears stale I2C records for this board using `deleteI2C.php?key=<mac>`.
	- Expands `sensorName` tokens and calls `upDateTableI2C(name, index)` per device.
	- Starts async HTTP server (`serverAsyn`) on port 80.
	- Attaches ElegantOTA and starts OTA endpoint.
6. If no sensors are found, logs `No Valid Sensor Found check wiring` and does not start Wi-Fi/TCP/OTA services.

Notes:
- The D6 interrupt setup is present as commented code only.
- `getBuildTime()` is available but not called from `setup()` in current flow.

## Main Loop
`loop()` runs:
1. `ElegantOTA.loop()` to keep OTA service responsive.
2. Accepts one TCP client via `server.accept()`.
3. Waits up to 5 seconds for command data; on timeout prints `>>> server Timeout !` and closes client.
4. Reads incoming bytes into `cmdFromClient[80]`, uppercasing each byte.
5. Drops excess bytes beyond buffer length to avoid overflow.
6. Routes command:
	- Prefix `ALL`: `getSensorData(cmdFromClient, results)`.
	- Otherwise: calls `performSystemTask(cmdFromClient, results)` to build response and apply side effects.
7. Sends `results` once with `client.print(results)`, closes socket with `client.stop()`, then logs payload to serial.
8. Feeds the loop watchdog (`lwdtFeed()`) after each handled client request.

## Command Contract
- `ALL`: returns sensor frame generated by `getSensorData()`.
- Non-`ALL` (for example `BLK`, `RST`, OTA/system commands):
	- response body is built by `performSystemTask(cmdFromClient, results)`.
	- side effects are executed inside `performSystemTask(...)`.

## Buffers and Limits
- `cmdFromClient[80]`: command input buffer.
- `results[512]`: outgoing response payload.
- `sensorName[100]`: underscore-joined sensor tags discovered at startup.
- `str[80]`, `Buf[80]`: scratch buffers (reserved/local use).

## Networking
- TCP command server: `WiFiServer server(PORT)` where `PORT = 8888`.
- OTA/web endpoint: `AsyncWebServer serverAsyn(80)` with ElegantOTA.

## ISR Status
`isr()` remains implemented and marked `ICACHE_RAM_ATTR`, but interrupt attachment is currently commented out in `setup()`.
